# Unityでの修正前後の比較手順

同一のマテリアル、視点、照明条件で修正前後を比較する。特定の描画モードで発生することを前提としない。

## 1. 比較環境の準備

- 再現プロジェクトのコピーを使用する。
- Unity、lilToon、GPU、ドライバー、Graphics APIを記録する。
- Sceneカメラ、露出、光源、マテリアルの設定を保存する。
- 修正前のシェーダーで症状が出る視点を記録し、比較用の画像を撮影する。

## 2. 独立した合成テスト（任意）

元のアバターとは独立した環境で縮退条件を検証する場合は、Quad、Sphere、Directional LightおよびlilToonマテリアルを用意する。

[directions.tga](directions.tga) をNormal mapとしてインポートし、圧縮とミップマップを無効にする。ノーマルマップ1stと異方性反射用ノーマルマップに同じテクスチャを指定し、同じUVと強度1を使用して法線と異方性方向を揃える。

| 項目 | 設定値 |
|---|---|
| 異方性反射の強度 | -0.5 |
| 異方性反射の適用先「反射」 | ON |
| 光沢のタイプ | リアル |
| 滑らかさ | 0.217 |
| 1st Specular タンジェント方向の幅 | 1.5 |
| 1st Specular バイタンジェント方向の幅 | 0.22 |
| 1st Specular 強度 | 0.4 |
| 2nd Specular 強度 | 0 |
| 反射の合成方法 | Screen |

対照条件としてノーマルマップ1stのみを無効にして比較する。

この合成テストで実際に黒い斑点が再現するかは未確認である。

## 3. 修正コードの適用

対象ファイル:

```text
Assets/lilToon/Shader/Includes/lil_common_frag.hlsl
```

修正前のファイルが `e698a2f` と同一であれば、[修正版](../Assets/lilToon/Shader/Includes/lil_common_frag.hlsl) に置き換えることができる。

Git管理下でパッチを適用する場合は、対象リポジトリのルートディレクトリで以下を実行する。適用可能であることを確認してからパッチを適用する。

```sh
git apply --check <パッチのパス>
git apply <パッチのパス>
```

パッチ: [fix.patch](fix.patch)

既存の `.meta` ファイルは保持する。Unityで再コンパイルした後、Consoleのエラーと対象のシェーダーパスを確認する。

## 4. 描画結果の比較

以下の各描画モードで修正前後を比較する。

- 不透明
- カットアウト
- 半透明
- 半透明（OnePass）
- 半透明（TwoPass）
- 屈折
- 宝石

黒い斑点が発生する条件では修正後の発生状況と周辺の外観差を確認する。修正前に発生しない条件でも、修正後に正常な外観が維持されるか確認する。

## 5. 回帰テスト

以下の設定や表示条件について修正前後を比較する。

- リアル光沢とトゥーン光沢。
- 異方性反射用ノーマルマップの有無。
- 髪・金属のハイライト。
- MatCapのみ、MatCap 2ndのみを使用する条件。
- ミラーUVおよび負スケール。

カメラ、モデル、光源を個別に回転させ、黒い斑点、光沢方向の急な変化、HDRピークの変化、反射方向の反転や崩れがないか確認する。

## 6. VRChatおよび異なる動作環境での比較

VRChatのテスト環境では、同じアバターを同じ鏡、距離、角度で比較する。

可能であれば、同一プロジェクトのスタンドアロンビルドを異なるGPUでも実行し、対応環境ではD3D11とVulkanを比較する。UnityのFrame Debuggerでパス名とキーワードを記録する。
